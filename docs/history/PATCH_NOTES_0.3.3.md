# BioKyn 0.3.3 audit patch notes

## Changes
- Added `assistive` to the `requestDigest` request type so the field is represented in strict TypeScript.
- Changed the constant-speed kinematics hard-reject rule to require at least half of a session's strokes to meet the low-variation threshold. Individual strokes retain their diagnostic flag.
- Restored `NextHandlerOptions.clientIp` and forward its result to the framework-neutral request for production rate-limit callbacks. The extractor must use trusted deployment metadata; do not blindly trust client-supplied forwarded headers.
- Corrected `encodeToken` to serialize the compact 96-byte redemption token rather than an issuance transcript.
- Updated package versions and README/security-review headers to 0.3.3. Updated corresponding checked-in declaration/runtime artifacts for the touched APIs.

## Verification status and remaining release gate
- Full build and test suite were not run: dependency installation timed out in this environment. The checked-in `dist` files were aligned manually for the touched changes, not regenerated by a successful compiler run.
- Siteverify idempotency remains process-local. Cross-node retries can still fail after the first node consumes a token; production multi-instance deployment requires a shared idempotency result store with atomic coordination. This is not fixed by this patch and remains a release gate.
- Independent cryptographic review and OPRF conformance testing remain required. Do not treat this version as production-certified.
